# 度量体系（D22/D23）

## 北极星
**人类结构性编辑率随时间单调下降** = `structural 类编辑数 / 交付集数`，按月滑动。

为什么不是完播率/转化率：它们受剪辑、投流、演员影响，不在你的控制闭环内，
拿它做北极星会让优化失焦。结构性编辑率是唯一同时证明"资产在复利"和"交付在变好"的指标。

## 六个数（每周看，`docs/metrics/latest.md`）
| # | 指标 | 定义 | 健康方向 | 报警线 |
|---|---|---|---|---|
| 1 | 首过率 | L0+L1 一次通过的集数 / 总集数 | ↑ | <0.5 |
| 2 | 人类编辑率 | 按 D11 八类分解，**必须分解** | ↓（structural 优先） | structural 上升 2 周 |
| 3 | 判官-人类一致率 | 每 rubric 维度的成对一致率 | ↑ | <0.78 → 自动关闸 |
| 4 | 规则命中率与净收益 | 每条 canonical 规则的 hit_count / 误报率 | 命中>0 | 90 天 0 命中 → 退役 |
| 5 | 检索命中率与增益 | 1 档：检索到 k≥1 的比例 / 开关 A/B 的质量差 | ↑ | 增益 ≤0 → 检索有害 |
| 6 | 单集成本 | token $ + 墙钟 + **你的分钟数** | ↓ | 你的分钟数上升 |

**第 6 项里"你的分钟数"最重要。** 如果系统让你更忙，它就是在亏钱，不管质量多好。

## 辅助（诊断用，不上仪表盘）
- 缓存命中率（局部重编译是否真的生效）
- 锚点恢复率（bookmark / appendix / fuzzy / failed 的分布）
- CI bypass 次数（架构腐烂的先行指标）
- L3 canonical 规则数（接近 120 上限时该做合并了）
